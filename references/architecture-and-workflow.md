# Rust 原生移植架构与高效推进

## 可复用的模块边界

本模式从《旷野之息》macOS 移植的 Cargo workspace、Rust 源码组织与 Swift 启动器提炼。下列 `nx*` 是参考名称，不是要求目标仓库必须具有的命令或包名；先映射现有模块，缺失时才创建。

| 职责 | 参考模块 / 语言 | 边界与产物 |
| --- | --- | --- |
| 容器与资源 | `nxfs` / Rust | 读取容器、升级与 RomFS，解析 NSO 和游戏身份；输出可校验资源与模块清单 |
| 共享 ABI | `nxabi` / Rust | 改写器与 runtime 共用上下文布局、入口约定、常量；避免双方各自维护偏移 |
| 离线改写 | `nxpatch` / Rust、必要汇编 | 指令分类、改写、跳板与等价检查；输出与原 build ID 绑定的改写产物 |
| 扫描与诊断 | `nxscan` / Rust | 模块分析与定位；按需运行，不混入运行时热路径 |
| Shader 转换 | `nxshader` / Rust → MSL | 解码、转换、批处理与缓存；独立验证语义并供 host 使用 |
| 原生运行时 | `nxhost` / Rust | 装载、guest 入口、内存、线程、SVC/IPC、服务、输入、音频及 NVN → Metal |
| 平台桥接 | Rust 的 Apple API bindings，必要时 C/Objective-C++ | 显式管理对象、回调与线程生命周期；分别适配 AppKit/UIKit 等平台能力 |
| 启动器 | Swift | 资源选择、准备、启动/停止、预编译入口与状态；复用同一准备逻辑 |
| 开发编排 | Python/Bash | 参数校验、调用原生工具、缓存失效、打包签名与证据归档 |

数据流：

```text
本地源包 → 资源/版本识别 → NSO + RomFS
                          ├→ 离线改写 + 共享 ABI → 平台装载 → 原游戏 ARM64 代码
                          └→ Shader 转换 → 平台 shader 缓存
原游戏 → SVC / IPC / SDK → host 服务、输入与音频
原游戏 → NVN 录制 → 命令回放 → Metal 提交/完成 → 实际窗口
```

原生直接执行仍需解决指令、OS ABI 与平台签名约束。macOS 动态装载和 iOS 构建期链接的产物路径分开，详见 [runtime-and-platforms.md](runtime-and-platforms.md)。

## 通用核心与游戏适配分离

- 核心负责可复用的格式、指令和服务语义。游戏适配配置承载 Title ID、版本/build ID 集合、SDK 布局差异、已验证补丁与启动参数；不要把参考游戏的常量散落到通用逻辑。
- 先核实旧实现的输入输出与所有权，再迁移行为。新版 RELR/GNU hash、TIPC 或音频 revision 等属于待核实差异清单，不是所有游戏都需要的固定补丁集。
- ABI/FFI 使用明确布局与定宽类型，检查大小、对齐、指针范围和所有权。将 `unsafe` 限制在可审计边界，说明有效地址、生命周期与同步前提；不让 Rust panic 穿越外部 ABI 边界。
- 运行时按装载/内核、服务、图形、音频和输入拆分。图形再区分命令录制、对象与资源、状态、shader、回放、读回与 query，保留跨提交资源生命周期，避免一个全局可变状态包办全部语义。
- 复用成熟原生库前检查许可、平台和 ABI；固定依赖版本，保留来源及版权。不要为“通用”预先实现与当前游戏路径无关的全部系统服务。

## 每轮推进一个可见阻塞

1. **盘点可复用资产**：读取清单、构建入口与实际源码，列出已有能力、版本差异和最短路径上的缺口。若参考工程不可用，依据上述职责映射当前仓库，不能卡在寻找某台机器的目录。
2. **建立可重复准备流程**：配置源资源目录、独立数据目录与目标平台；记录模块身份、改写器/转换器版本和准备结果。准备、验证、运行可独立调用，启动器复用同一入口。本文不假定目标仓库已有同名脚本。
3. **贯通最小纵向路径**：模块装载 → 原入口 → 必需服务 → 首次有效回放 → 有内容的呈现 → 输入引起实际状态变化。为当前阻塞补齐真实语义，避免先堆积空桩或只统计初始化数量。
4. **缩小修复范围**：以线程栈、模块相对地址、服务请求、资源生产消费链定位层次；提取最小指令、ABI、并发或 GPU 复现。修复底层语义后回到原游戏路径验证。
5. **复用增量产物**：只重建受影响模块；按输入身份、工具版本、目标平台与选项失效缓存。Shader 离线转换与运行时 pipeline 预热分别统计，保留成功项、重试失败项，避免每轮清空全部缓存。
6. **再优化性能**：先确认正常路径正确，再比较同场景的 release 构建、冷热缓存、CPU/GPU 时间与同步开销。诊断版保留符号，有界采集；不要用跳过绘制、返回伪成功或持续忙轮询换取表面速度。

已有工程以实际 wrapper 和 Cargo 包定义为准，选择受影响包的检查/测试及目标平台构建；不要复制不存在的命令。单元验证、构建、目标设备运行与自然游戏推进分别记录。完整验收规则见 [validation-and-cases.md](validation-and-cases.md)。

## 路径与工具可移植性

Skill 内引用使用相对路径。目标仓库与可选参考仓库由当前任务提供或从工作区发现；源包、密钥、缓存和设备配置通过项目参数或本地配置传入，不写死用户名、主目录、卷名或设备编号。工具缺失时报告具体缺项和可继续的工作，不假设特定 Agent、MCP、GUI 自动化产品或本机私有脚本始终存在。
