# 验收与历史案例

## 验证时机与批次

遵循 [SKILL.md](../SKILL.md) 的实施节奏：先完成当前目标内的全量实现，再统一测试。下列证据阶梯描述可报告结论所需的证据，不要求每实现一层就单独构建、安装或启动游戏。

统一验证前整理改动与验收项的对应关系，复用已有用例，补齐必要回归。先执行检查、受影响模块测试和构建，再对同一产物集中验收；一轮运行尽量覆盖菜单、场景、输入、音频和退出，读档按要求另起进程。多平台只覆盖本次目标范围，各自记录结果。

对可独立执行的检查汇总结果；无法执行的项标为阻塞或未测。失败按根因分组集中修复，每批修复后只重跑失败项和受影响项；共享语义变化相应扩大回归范围。最终构建完成受影响路径验收后停止，不因“再保险”反复启动整套测试。历史案例中的复测次数不是固定要求，时序或偶发问题按实际复现条件安排重复。

## 证据阶梯

| 可报告的结果 | 最低对应证据 | 不能据此推断 |
| --- | --- | --- |
| 构建/签名通过 | 退出状态、包身份、签名验证 | 已启动或可玩 |
| 原代码进入 | 同一运行的模块身份、初始化与 nnMain trace | 有游戏画面 |
| GPU 初始化 | 资源、函数、pipeline 创建 | draw/dispatch 已执行 |
| GPU 执行 | 实际回放、提交、完成、读回 | 窗口正确或输入可用 |
| 有内容的首帧 | 目标图像及实际窗口 | 菜单、关卡或稳定运行 |
| 交互成功 | 输入前后可见状态变化 | 其他输入设备或全流程可用 |
| 可玩片段 | 自然推进的明确路径和结果 | 全关卡兼容、完整游戏完成 |
| 存档可用 | 游戏内保存、正常退出、新进程加载并核对状态 | 其他存档/版本可用 |
| 音频生成 | 格式、帧数、非零 PCM 等 | 实际听感与音画同步 |
| 目标平台通过 | 同构建、指定设备实测 | 其他 OS/芯片/设备通过 |

每个验证批次保存：源码 commit/dirty 摘要、模块身份、构建或包 hash、运行 ID、设备/OS、数据目录、诊断配置、执行步骤、实际结果、日志/截图位置；同一批次共享构建元数据，不为每个代码编辑创建一次运行记录。日志与原始资源留在忽略目录，公开记录脱敏。

验收路径按游戏定制，不强行设定相同按钮：标题 → 菜单 → 场景加载 → 移动/镜头 → 核心机制 → 保存 → 正常退出 → 新进程读档。输入验证要观察结果；“按过按钮”不等于成功。长按和组合键要正确释放。

编写自动化测试前先探索真实应用并核实状态/交互，再按框架能力用动态定位与显式等待。游戏画面缺少可访问性树时使用已验证的图像、坐标或输入通道，并记录分辨率与窗口状态。本 skill 不要求 Android ARTEMIS 作为 Apple 移植依赖；目标项目另有测试规则时遵守。

## 可复制的记录骨架

```markdown
# 游戏 / 版本 / 平台 / 日期
- 输入身份：Title ID、Control 版本、NPDM、模块 build IDs
- 构建：源码状态、包 hash、签名结果
- 运行：run ID、设备/OS、数据目录、缓存及诊断配置
- 本批次改动范围与待验证假设：
- 已执行检查及结果：
- 实际交互路径及可见结果：
- 证据位置：
- 未验证/已知失败：
- 失败根因分组与待集中修复项：
- 下一批次的定向复测范围：
```

阶段结束同步 README 和状态页；历史失败保留日期及所属构建，明确后续是否已解决。暂停时记录现场、未验收改动与恢复点，不继续启动新运行。

## 可迁移案例

以下是既有移植记录提炼出的经验，不是对当前目标游戏的验收承诺。使用时在目标仓库记录实际源码版本、模块身份与证据位置；无需获取案例的原始工作目录。

### 跨版本迁移

赛车游戏移植曾通过复用通用改写器支持新版本，但 Mac 与 iOS 构建脚本的目标版本不同。可复用做法是按实际 build ID 选择配置，分别维护平台支持矩阵、准备目录和缓存；不要复制旧版地址补丁，也不要把 Mac 可玩推断为 iOS 可玩。

### Rust 原生兼容层的纵向推进

《旷野之息》的 macOS 移植复用 Cargo workspace，将资源解析、离线改写与 host runtime 接通，再按真实阻塞补齐新版装载/启动 ABI、IPC、NVN 对象、线程和音频协议。具体模块职责见 [architecture-and-workflow.md](architecture-and-workflow.md)。这一模式复用的是兼容层与诊断能力，游戏版本、偏移和 SDK 布局仍需重新核实。

实际行为曾暴露条件变量丢失唤醒、纹理双向一致性和图集刷新问题。地形高度读回、池塘共享存储等根因与验证方式见 [graphics-and-debugging.md](graphics-and-debugging.md)。复测使用新进程与正常诊断配置；单个场景恢复不能外推为全部画质正确。

### 初始化不等于运行

早期 iPad 原生探针能进入原 nnMain、完成重定位并创建大量 Metal 函数与 pipeline，但绘制只录制而未回放，实时输入也未接通。下一步应贯通命令回放、实际呈现、输入消费与音频生命周期。不同项目、构建和平台的成功不能拼成一次从未发生过的完整验收。
