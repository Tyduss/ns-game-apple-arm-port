# NVN → Metal 与实景排障

本参考用于设计实现及统一测试后的排障。先集中完成目标范围内已明确的图形修改，再按受影响语义批量执行 GPU 用例和游戏验证；以下诊断项不是逐条修改后抓帧、读回或重启游戏的要求。提前探针遵循 [SKILL.md](../SKILL.md) 的实施节奏。

## 从提交链定位黑屏

分别计数：命令录制、回放、draw、compute dispatch、提交、GPU 完成、present。再看渲染目标是否有内容、实际窗口是否显示同样内容。present/FPS 持续增长仍可能只是黑帧；shader 函数或 pipeline 创建成功也不说明 shader 已执行。

在有界捕获中把模块 build ID、帧、draw、shader hash、顶点/索引、常量缓冲、纹理及 view、渲染目标和 pass 状态关联起来。原始渲染目标 PNG 的颜色值与实际窗口显示可能不同，二者分开检查。

卡死时采集线程栈、队列/事件状态和 GPU 完成信息。单份等待栈不能独立证明 GPU 死锁；还要检查虚拟 CPU 亲和性、条件变量漏唤醒、编译和实际待处理工作。

## 命令与对象生命周期

- 普通纹理绑定可能录制时复制句柄，Deferred 绑定则保留地址并在提交时读取；以目标 SDK 为准。
- 嵌套命令保留所调用块的生命周期；控制内存索引或地址复用不能让已录制调用指向新内容。
- 回收限定正确 owner/recorder/generation。另一录制器复用临时地址，不能删除长期缓存的顶点绑定。
- 屏障、延迟 clear、render pass 边界、query、条件渲染都需要真实语义。Query 的时间戳不是可见样本数；同步 CPU 读取结果虽能先保证正确，也需记录等待开销。
- 对动态 Alpha Test 阈值、深度/模板、offset、比较采样及 sampler 数量逐项追踪，不只检查 shader 是否编译。

## 纹理与双向一致性

建立每个资源的来源、布局、CPU/GPU 最新写入者及同步状态。缓存键包含格式、mip、layer、范围和 swizzle 等实际影响视图的字段。

1. 检查 SDK builder 字段，分块/GOB、行距、层对齐、mip 与 3D 深度；不要用固定前缀偏移推断所有字段。
2. CPU → GPU：Flush/WriteTexels 的范围必须传播到采样路径；同一提交内再次修改也应刷新。上传和缓存散列来自同一快照，避免把未上传的并发写入标为已同步。
3. GPU → CPU：InvalidateMappedRange 应同步相交的 GPU 写入，恢复 guest 所需布局，仅改请求字节。部分读回或读回期间的新写入不能清掉整资源脏状态。
4. 分块纹理 WriteTexels 若只写 Metal，不更新 CPU 存储，下次 Flush 会把旧数据上传回来；同时处理 mip、层、局部范围和 stride。
5. 符合条件的线性纹理可考虑共享底层存储，严格检查类型、格式、对齐、行距、范围和同步顺序。Apple 统一内存不意味着两个独立分配的资源自动别名，也不免除 GPU 完成同步。
6. 未 resolve 的多重采样、不支持的布局明确报告，不以静默零数据冒充成功。

### 两个实际根因

- **BOTW 小腿陷地**：GPU 高度纹理没有通过映射失效操作读回；CPU 高度查询取得零，原游戏 IK 再将骨架压低。修复 GPU → CPU 读回后脚部与草地恢复。不要先改角色 Y、Havok 碰撞或骨骼资源。
- **BOTW 池塘水色异常**：GPU 写入 1×1 线性纹理，但 CPU 材质表读取另一份全零存储。符合条件的纹理改用共享底层缓冲后，颜色表与水色恢复；不需要强制指定水色。

诊断时检查同一次绘制实际绑定常量与 guest 原始内容。临时更新缓冲可使两者不同，这本身不是 bug；二者都为零时应追踪上游生产者。给角色、进程和帧正确标识，不能把另一个角色的采样当成玩家数据。

## Shader 语义与验证

- 用独立最小输入验证实际 GPU 输出，不能只验证生成的 MSL 文本。包括符号扩展、寄存器重叠、负偏移、mip/layer 与边界。
- TEX texel offset 应按采样 mip 语义传递；按基础尺寸平移 UV 在较小 mip 上可能错误。
- 检查数组 gather 层号、LOD 返回编码、PCF、共享内存布局和对齐。实现 LDS/STS 不等于同时实现 barrier、原子与全部计算同步。
- 目标 SDK/设备不支持某功能时报告边界；不要根据当前 Mac GPU 推断 iPhone/iPad 能力。
- 缓存按转换器与选项隔离。预编译分别报告成功、复用、失败和不支持；失败项存在时不能报“全部成功”。离线 shader 缓存不等于全部 runtime pipeline 已预热。
- 首次编译未完成时跳过 draw 可能永久丢失只绘制一次的图集；正确性阶段优先保证绘制执行。但等待编译不必然修复缺字，还要检查 CPU 图集修改检测与上传时序。

## 避免诊断与性能误判

BOTW 首次死亡缺字曾在一次抓帧后消失，后来又复现。最终完整检查线性图集后，在两个关闭纹理跟踪的新进程中复测不同死亡路径。单次成功必须允许后续反例推翻。

性能按同一场景、窗口尺寸、构建、缓存冷热及验证层状态比较。分别统计 CPU 回放、同步读回、shader 编译、GPU 命令耗时和呈现；只轮询已完成结果的诊断可减少额外等待。GPU 命令时间合计不是整帧利用率。菜单 120 FPS、静止 30 FPS 或单段赛道 60 FPS 不代表全流程性能。抓帧暂停与冷编译长帧单列。
