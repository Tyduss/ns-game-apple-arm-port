# 执行层、ABI 与平台差异

## 输入身份与改写

常见分层是 `nxfs`（容器、升级、RomFS）、`nxpatch`（离线指令改写）、`nxhost`（运行时、服务和 Metal）。这些是参考项目模块名，先核对目标仓库再调用命令。

- 按容器内容关联本体、升级与 DLC，核对 Control 版本、NPDM 架构和 main/sdk/subsdk/rtld 身份。准备目录中的 main 必须与当前选择的升级包一致。显示版本不能硬编码为参考游戏的版本。
- 以模块 build ID 门控游戏专用补丁；校验原指令/字节、跳转目标、表宽与范围，不满足就拒绝改写。通用规则与游戏补丁分开。
- 重点检查 x18、SVC、系统寄存器、间接调用及跳转表。不要把 x18 当普通可自由使用的 Darwin 寄存器；改写需保留 guest 寄存器、标志、栈、内存副作用和目标地址语义。
- 等价验证输出通过、失败与未测数量；对寄存器重叠、负偏移、边界表项和间接分支补充覆盖。有限随机样本不证明全部输入；模拟器等价检查也不替代目标机陷阱/调用路径验证。
- 装载器检查段边界、权限、BSS、TLS、导入与重定位。BOTW 新版适配遇到 RELR、GNU hash 和启动函数参数变化；按实际模块解析，不假定参考游戏 ABI 永久不变。

## Horizon 与 Darwin 适配

| 部分 | 需要核实的语义 | 典型误区 |
| --- | --- | --- |
| IPC | 实际服务、命令、输入输出大小、句柄/事件所有权、协议版本 | TIPC 回复套用 CMIF 魔数；未知服务返回成功 |
| 内存 | guest 页粒度与 host 页粒度、映射覆盖、只读区、TransferMemory 引用生命周期 | 把 4 KiB guest 子页当作天然具有独立 host 页保护 |
| 线程 | 虚拟 CPU、亲和性、优先级、线程查询、唤醒和关闭 | 固定亲和线程被归到另一 CPU；单线程串行运行被当成完整多核支持 |
| 条件变量 | 等待者登记、guest 等待标记与解锁的顺序 | 先解锁，生产者看不到等待标记而跳过唤醒 |
| 共享状态 | 时间上下文、HID 序列锁、快照一致性 | 初始化一次后永不生产实时状态 |
| FS/存档 | 路径、提交/刷新、挂载与退出语义 | 用源游戏目录或其他模拟器真实存档作为实验目录 |
| NVN 对象 | SDK 版本、对象尺寸、字段偏移、复制与销毁 | 对所有字段机械加固定偏移；指针索引因复制/复用失效 |

BOTW 条件变量修复的关键是先登记等待者并设置 guest 标志，再释放 guest 锁；原实现可出现“队列已有消息、消费者仍睡眠”。应使用能让生产者抢先执行的并发回归，而非增加轮询睡眠掩盖问题。

采样器等 SDK 内联对象还要检查相邻内存保护与按值复制；兼容层展开字段超过对象大小会破坏别的对象。资源注册表需跟踪 owner/generation；扩大容量只解决容量问题。

## macOS

- 检查现有签名/权限及 guest 代码装载方式，沿项目已有路径处理可执行内存；不要假设任意可写内存都能执行。
- 使用真实打包应用及 helper 验证。启动器、guest runtime、数据目录、退出协议分别确认；进程存在不证明窗口与游戏成功。
- 保持应用标识和签名稳定，避免无关签名变更使已有权限失效。重建前正常结束旧游戏，避免二进制、缓存和进程版本混用。
- 键盘与真实手柄分别验收：按下/释放、持续摇杆、多个按键同时按、窗口失焦、全屏和停止操作。避免把菜单按键映射直接当成游戏内操作说明。

## iOS / iPadOS

- 先检查当前源码的部署路线与实际签名配置。一种已采用的原生移植路线在构建时将改写代码链接入应用，并为 `iphoneos` 预编译 shader；不能照搬 Mac 启动时动态装载策略，也不能把 `macos` metallib 当成 iOS 产物。
- 检查 SDK、target triple、deployment target、设备、provisioning 和最终 entitlements。虚拟地址空间、可用内存和签名能力以实际设备与配置为准；不把历史免费/付费账号限制写成永久承诺。需要最新平台规则时查 Apple 官方文档。
- 对构建脚本里的版本默认值作专项核对。Mac 与 iOS 脚本可能仍指向不同游戏版本；“Mac 支持新版本”不能自动修改为“所有平台支持”。
- 将重定位地址空间、内存压力、前后台暂停、音频中断、触摸控制和控制器断连作为设备验证项。检查输入释放，避免切后台后持续按键。
- 模拟器只可验证覆盖到的壳层/UI；签名代码执行、内存布局、GPU 支持与可玩性需要目标真机结果。

## 音频

按实际 SDK 的 AudioRenderer revision 验证结构大小、对齐、状态值、内存池、voices、effects、sink 和事件。REV4 的 stopped-state 初始化经验不能直接套给 REV15。

分阶段证明：协议配置被接受 → Start/Stop 与回调 → 空混音时钟/事件推进 → 活跃 voice/解码/混音 → 非零 PCM → 实际播放及同步。空 PCM 回调运行不是游戏声音；非零 RMS 也不证明扬声器听感。

排查回调线程、锁顺序、semaphore、停止时 join、OSStatus、输出格式及前后台恢复。后台音频修复只有构建记录时，下一步先安装新构建验证生命周期，不能引用旧 trace 当成功。
